The ord/1 protocol

ord/1 is a small set of public files and one decision function. A shop that publishes the files lets any customer, agent or helper settle a returns dispute under the terms that applied on the day of purchase, without a platform in the middle and without a server.

Adopt it as a shop

  1. Publish your returns terms as a versioned ord-terms/1 JSON file. Keep every old version at a stable address.
  2. Print the version and its fingerprint on every receipt (ord-receipt/1). The fingerprint is the SHA-256 of the file's canonical JSON.
  3. Add a resolution block to your agent-manifest.json that lists the versions, your offers and this desk.
  4. Optional: publish a representative agent network under a separate path such as /agents/, so other sites can load it by URL. Its instructions are your public mandate.
  5. Optional: host a case page that recomputes the outcome with your own copy of the decision function before you confirm. The demo shops include one.
"resolution": {
  "protocol": "ord/1",
  "desk": "{{DESK_URL}}",
  "engine": { "name": "ord-evaluate", "version": "1.0.0", "sha256": "{{ENGINE_SHA256}}" },
  "terms": {
    "current": "3",
    "versions": {
      "2": { "url": "./terms/v2.json", "sha256": "sha256:…", "effective_from": "2026-03-01", "effective_until": "2026-10-14" },
      "3": { "url": "./terms/v3.json", "sha256": "sha256:…", "effective_from": "2026-10-15" }
    }
  },
  "offers": [ { "id": "credit-115", "kind": "store_credit", "percent_of_refund": 115, "applies_to": ["eligible"] } ],
  "representative": "https://shop.example/agents/shop_claims",
  "case_page": "./backoffice.html"
}

The outcome and its fingerprint

The decision function evaluate.js takes the pinned terms, the receipt and the claim. It reads no clock, no network and no storage. It returns a decision (eligible, not_eligible, needs_review or incomplete), the remedy, the refund value in cents, who pays return shipping, and every check with its clause.

The fingerprint is the SHA-256 of the canonical JSON of the engine (name, version and source hash), the terms hash, the receipt hash, the claim and the outcome. Canonical JSON sorts object keys and allows integers only. Two parties with the same inputs get the same fingerprint.

Language models never set the outcome or its amounts. They help a person describe what happened, explain the result, and talk to the other side's agent. Shop offers are published data, so the desk computes their value too.

Case files and links

A case file (ord-case/1) holds the receipt and a list of events: filed, outcome, accepted, confirmed, declined and review_requested. Each event's hash covers the one before it, so a step that was changed or removed without recomputing the hashes after it shows on the verify page. Events are not signed: whoever holds the file can rewrite it from any step and recompute the hashes. Outcomes do not rest on the chain, because each party recomputes them from the terms, the receipt and the claim.

Cases travel as links. The shop's handoff link (case.html#handoff=…) and the case links between the parties (#case=…) carry the compressed JSON in the URL fragment, which browsers do not send to web servers. The desk's host receives nothing.

Source and tools

Everything on this site and the two demo shops is in github.com/taronsung/open-resolution-desk under the Apache License 2.0. These parts are meant for reuse:

  • protocol/v1: canonical JSON with SHA-256, the decision function and hash-chained case files, with unit tests. A shop or an agent can run the same code to check an outcome.
  • tools/check_agentic_site.mjs: checks any agentic site's published manifest, network definitions and links.json against the MVP specification, the way a browser on another origin reads them, and follows the peer networks they name. It validates each network with the runtime's own parser and validator.
  • tools/serve.py: a static server that sends the headers GitHub Pages sends, for testing two origins on one machine.
  • The desk's public procedure guide, {{DESK_URL}}/agents/desk_preview, which any agentic website can load by URL to explain the procedure to its visitors.

Limits of this demo

  • Steps are hash-chained, not signed. The chain shows a careless edit, but whoever holds the file can rewrite it and recompute the hashes, and nothing shows who recorded a step. The desk therefore cannot prove that a shop confirmed a case. A production version would sign events with keys each party publishes in its manifest.
  • Facts are recorded as stated. When the shop disputes one, the case is marked for review by a person. The demo records the request, and no reviewer is on duty.
  • The decision function runs as a site action on the desk and as a pinned module on the shop. The runtime's coded-tool sandbox needs a response header that static hosts such as GitHub Pages cannot set.
  • Everything is tab-scoped. There are no accounts, notifications or reminders: links are the transport.
